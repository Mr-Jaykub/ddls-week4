Can you trust
a predicted shape?

A cancer researcher has an AI-predicted 3D model of p53 — a protein that goes wrong in roughly half of all human tumours. A chemist is waiting on her for the exact positions to aim the first compounds at.

She had already chosen them, from the picture. The model draws every position with the same clean, confident line — and she had read that as the model being sure.

So the request changed

Park 18–28 as a validation project. Instead: flag every position in 94–312 the model is not confident about, worst first, one rule for all. Not good targets — a caution list.

Two kinds of confidence

Which number
answers it?

The AI marks its own work — in two different ways.

pLDDT — predicted Local Distance Difference Test

“Is this bit in the right place?”

One score per position. Scored 0–100, higher is better. Below about 70 the model is telling you not to rely on it.

PAE — Predicted Aligned Error

“Are these two bits right relative to each other?”

One score per pair of positions. An expected error in ångström — a distance, so smaller is better.

  • Her question is about single positions, so pLDDT answers it.
  • The file she pointed me to held only PAE — the per-position scores were inside the model.
  • It is her protein: sequence matches exactly, 393 positions, no mutations.

The catch

The list found
her own edge

  • Her range runs about 20 positions past where the protein stops being folded. Those positions are floppy, not faulty.
  • So the shortlist is mostly a map of where she drew the boundary, not of problems inside the fold.
  • The only 2 hits inside the fold sit right on the line — move the cut-off from 70 to 65 and both disappear.

The other metric, finally used

Where the confident
fold ends

“Is that tail actually attached to the core?” is about relative placement — so PAE answers it, not pLDDT. The matrix was in the file she sent me.

  • 28.1 å is near 31.75, the highest this file can express. The model is not placing the tail badly — it does not know where it goes.
  • Two measures, two questions, both turn at 293.

What she got, and what is hers to decide

She got 22 positions, worst first, with the rule printed on the list so the chemist can re-apply it himself.

The confident fold ends near 292, not 312. I screened her range as set — but this is a boundary decision, and it is hers.

Keep 94–312 and the list mostly describes her own edge. Move to 94–292 and it becomes two borderline positions, both gone at a cut-off of 65.

Found the companion file had no per-position scores at all. Drafted questions for my second interview round.

Verification — why these numbers should be believed

Running one script twice proves nothing. The screen was rebuilt independently — separate parser, separate libraries, no shared code — and returned the same 22 positions, same ranking, same values. The file stores each confidence twice; both columns agree, 393 of 393.

  • Me: ran the interview, chose the questions, set the cut-off, decided what to refuse.
  • The cut-off was chosen after I saw the files — reproducible, but not blind. The report says so.
Limits & next step

What this
cannot tell you

  • A confidence score only says where the model put an atom — nothing about the chemical tags the cell adds, the molecules p53 grips, or the fact that real p53 works as a group of four. This model is one copy, alone.
  • A high score is not a good target — it says nothing about whether a drug could bind. She asked me not to pick targets, and I didn’t.
  • I also never checked her 94–312 range against a source — and the whole finding is about where that range ends.

Next experiment: compare positions 183 and 185 against a real, measured structure — the one result a cut-off cannot settle.
